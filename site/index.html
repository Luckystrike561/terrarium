What it does

Agents become characters

Each agent gets its own character. It types at a desk while its agent edits files or runs commands, reads while it searches, and shows the agent's own one-line intent above its head. When the agent needs you, it queues at the CTO's office. When it is idle, it rests in the lounge.

herdr integration

The herdr module shows every agent herdr manages, named after its workspace, with its status, task and pending approvals. herdr servers on other machines join the same office over SSH.

A standalone server

One Node.js process watches your agents and serves the office to any browser. It never modifies your agents: its data lives in ~/.terrarium/, and the only file it writes elsewhere is ~/.claude/settings.json, when you approve Claude Code hooks.

Supported agents

herdr plus agent modules. Pick any combination with --provider, for example --provider herdr,omp,codex. Every agent module shows its CLI's sessions on this machine, with or without herdr.

Approvals means the office shows the agent waiting for your approval. Clean exit means the CLI records its own exit, so the character leaves the moment the session ends. Without it, the character leaves once the session has been quiet for a while. Inside herdr, herdr adds pending approvals for every agent.

Status only in herdr

An agent in a herdr pane whose CLI has no running agent module shows herdr's status, name and task, but no tool activity. That is always the case for Amp, which keeps its threads on ampcode.com, and for agents on herdr servers reached over SSH, whose transcripts are files on the other machine. For every other CLI, add its id to --provider.

Getting started

Needs Node.js 22.13 or later and at least one supported agent CLI or herdr. Terrarium runs from source: the terrarium package on npm is unrelated.

  1. Build

    git clone https://github.com/Luckystrike561/terrarium.git
cd terrarium
npm install
npm run build

  2. Run with your agents

    node dist/cli.js --provider herdr,omp,codex

    List any module ids, comma-separated. The choice is saved in ~/.terrarium/config.json and reused by later runs. Without --provider, the first run watches Claude Code.

  3. Open the printed URL

    The server prints http://127.0.0.1:<port>/?token=…. Treat it as a secret: its token lets a browser install hooks and add SSH connections. Add --port 3100 for a fixed port.

Quick start per agent

Each module reads its CLI's own session store, so there is nothing to configure in the agent. Open a card for the command, the directory it reads and the Docker mount.

herdr

node dist/cli.js --provider herdr,omp

Reads herdr's socket at ~/.config/herdr/herdr.sock. Add the module id of every CLI you run in herdr panes to get their tool activity. herdr servers on other machines join from Connections in the office, over SSH.

Docker

ghcr.io/luckystrike561/terrarium:latest (amd64 and arm64) runs herdr and omp on port 8790 by default. 

docker run -d --name terrarium \
  -p 127.0.0.1:8790:8790 \
  -v "$HOME/.config/herdr:/home/node/.config/herdr:ro" \
  -v "$HOME/.omp/agent/sessions:$HOME/.omp/agent/sessions:ro" \
  -v terrarium-data:/home/node/.terrarium \
  ghcr.io/luckystrike561/terrarium:latest
docker logs terrarium   # prints the URL with its token

For other agents, add the mount from their card and pass your own arguments after the image name, for example … terrarium:latest --provider herdr,omp,codex --host 0.0.0.0 --port 8790. Keep the host port equal to the container port. The image runs as UID 1000: if id -u differs, add --user "$(id -u):$(id -g)". Claude Code is host only.

The user guide covers every mount, connections, options and troubleshooting.
